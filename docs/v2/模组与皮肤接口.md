# 模组 · 皮肤 · 游戏目录接口（原型只用这里列出的字段）

来源：最初根据本机 1.2.12 拆出的 `mods.js`、`skins.js`、`character-schemes.js`、`resource-mods.js`、`gamelib.js`、`home.js` 整理（2026-11-03）；现在基线是 1.3.2，以仓库源码为准。文中标明「1.2.12 时的记录」的内容只作参考。
回放部分见 [回放接口.md](回放接口.md)。

## 游戏目录（概览页）

**发出：** `gameProfilesGet`、`gameProfileSetActive {id}`、`gameProfileAddPath {directory, activate}`、`gameProfileBrowse`、`gameProfileUpdate {id, label, edition}`、`gameProfileRemove {id}`、`gameProfileOpen {id}`、`gameScanQuick`、`gameScanDeep {drive}`、`gameScanCancel`

**收到 `gameProfiles`：** `profiles[]` 每项包含 `id`, `label`, `edition`, `editionLabel`（国服 / 国际服 / TapTap / 自定义）, `directory`, `directoryExists`, `exeName`, `valid`, `active`

**扫描：**
- `gameScanQuick` 会查 Steam 库、注册表和常见位置；`gameScanDeep {drive}` 遍历整个盘，`gameScanCancel` 中途取消。
- 扫描过程中收到 `gameScanProgress { mode, running, message, current }`。
- 扫描结束收到 `gameScanResult { mode, candidates[] }`，每个候选是 `{ directory, editionLabel, exeName, valid, source: steam|registry|common|deep, alreadyAdded }`。
- `valid=false` 表示"没检测到标准 Unity 结构"，界面上标「结构可疑」。可选的盘符在 `gameProfiles.drives` 里。
- ⚠ **实测（1.3.2，2026-11-03）**：快速扫描不只返回吉星派对，Steam 库里其他 Unity 游戏也会列出来（例如 Malody、缺氧、RimWorld、The Bazaar），区服标成「自定义」。所以新界面只把 `AstralParty*.exe` 放在前面，其余折叠起来，防止误加。
- ⚠ 同一个原因（`DetectExe` 的 Unity 兜底）也影响首次启动：`SeedFromLegacyIfEmpty` 会把这些游戏**全部加进列表**，并把排第一的设成当前游戏。修改版已让 `EnumerateGameDirectories` 只认 `AstralParty*.exe`（Steam 库这一路，也影响 `modDetect`）；注册表和常见位置的扫描没改，所以折叠还要保留。
- `gameScanProgress` 的 `running=false` 表示取消或出错（比如「已取消深度扫描。」），这时**没有** `gameScanResult`，不能显示成「没找到」。
- 首次使用引导用的消息：`gameScanQuick` / `gameScanDeep` / `gameScanCancel`、`gameProfileAddPath {directory, activate:true}`、`gameProfileBrowse`、`modInstall`。程序启动时，概览可能赶在自动添加游戏之前就要过 `modStatus`，那份没有 `gameDirectory`，收到带当前游戏的 `gameProfiles` 后要再要一次。
- 原版里国际服目录（8vJXnINT）被记成了「自定义」区服；可以在设置 → 游戏目录 → ⋯ →「修改名称和区服」里改成国际服，这会影响按 ID 下载回放时默认用哪个服务器。
- 回放库设置 `librarySaveSettings { libraryRoot, autoMaintain, keepInGame, workshopUrl }`：缺 `workshopUrl` 时宿主保留原值；但缺 `libraryRoot` 会被当成"用默认位置"，缺 `autoMaintain` 会被当成关闭。所以每次都要四个字段一起发。
- 原版**没有首次使用引导**，没有游戏目录时只显示一句空状态提示；修改版的引导在概览页（`v2-shell.js`）。

**启动：** `launchGame {bypassSteam}`；`setSteamBypass {enabled}`，宿主会用 `steamBypassSync` 推回当前值。
- 「绕过 Steam」和加载器设置里的 `steamBypassEnabled` 是**同一个开关**。
- ⚠ 刚启动游戏的那几秒里，**不能改启动方式**：游戏启动早期会读这个配置，这时改动会混进刚启动的这一局。原版的做法是启动后短时间锁住这个选项。

## 模组

**发出：** `modStatus`、`modDetect`、`modInstall`、`modCheckUpdate`、`modUninstall {force}`、`modPickImport`、`modBrowse`、`modToggle {fileName, enabled}`、`modDelete {fileName}`、`modReadConfigFields {fileName}`、`modSaveConfigFields {fileName, fields}`、`modOpenConfigRaw {fileName}`、`modReadLoaderConfig`、`modSaveLoaderConfig {config}`、`modSaveSpeedhack {speedhackBaseSpeed}`、`modOpenModsFolder` / `modOpenSdkFolder` / `modOpenLogsFolder`、`modPickPackageFile`、`modImportPackage`

**收到 `modStatus`：** 内容是 `{ status, builtInMods[] }`

`status` 里的加载器状态：

| 字段 | 含义 |
|---|---|
| `installed` | 加载器已安装 |
| `loaderManaged` | 是本工具装的。为 false 时显示「文件不属于本工具」 |
| `loaderMissing`, `loaderDisabled`, `canRestoreLoader` | DLL 缺失 / 被停用 / 能否恢复 |
| `bundleLoaderPresent` | 程序自带的加载器文件是否完整 |
| `installedVersion`, `embeddedVersion` | 已装版本、程序内置版本 |
| `loaderRootExists`, `gameDirectory`, `gameRunning`, `message` | 加载器目录在不在、游戏目录、游戏是否在运行、提示文字 |
| `mods[]`, `sdk[]` | 模组列表、SDK 文件列表 |

GitHub 上的最新版本不在 `modStatus` 里，要点「检查更新」后由 `modUpdateCheck` 返回。

每个模组（`mods[]`）：`fileName`, `name`, `displayName`, `description`, `version`, `author`, `sdkVersion`, `sizeBytes`, `directoryName`, `modifiedUtc`, `enabled`, `permissions`, `dependencies[] {id, minVersion}`
- 「内置」标签：名字出现在 `builtInMods` 里就是内置模组

本机 1.2.12 内嵌的 9 个内置模组（从 DLL 里的 mod.json 读出来的）：

| id | 名称 | 版本 | permissions | 「可操作游戏」 |
|---|---|---|---|---|
| ActivityLogMod | 行为日志 | 2.4.0 | 1 | |
| FreeCameraMod | 自由相机 | 2.5.0 | 1 | |
| SpeedHackMod | 变速 | 2.4.0 | 4 | |
| CombatOddsMod | 战斗胜率助手 | 2.8.1 | 1 | |
| CardSkinMod | 手牌卡面皮肤 | 1.2.1 | — | |
| CharacterSkinMod | 角色皮肤 | 0.2.7 | — | |
| AutoThanksMod | 自动感谢 | 1.2.0 | 11 | ✓ |
| ForkDirectionMod | 岔路地块标记 | 1.2.0 | 1 | |
| TurnFocusMod | 回合置前 | 1.5.0 | 257 | |

> 2026-11-03 更新：用户已经通过「检查更新 → 更新到 v3.1.1」把游戏里的加载器升到 **v3.1.1**，内置模组也从 9 个变成 20 个（新增：AudioSkinMod、CharacterTransparencyMod、ChatDurationMod、HideHudMod、HomeBottomBarMod、LanguageUnlockMod、PveWaveForecastMod、QuickChatPlusMod、StarCoinShopMod、TurnClockMod、UnlockFrameRateMod）。用户确认保留这个版本，新增模组都开着。原来 9 个模组的配置在更新后都保留了。上表是 1.2.12 时的记录。

作者都是 CesiumLoader。⚠ 原版界面只解释了 `permissions` 的第 2 位（值为 2，可操作游戏），1、4、256 这几位分别代表什么还没查到。
- 「可操作游戏」：`permissions & 2`（模组声明了会模拟出牌、掷骰这类操作）

**模组配置**（`modConfigFields`）：`{ fileName, fields[] }`，每项 `{ name, kind, comment, boolValue, numberValue, stringValue }`
- `kind` 有五种：`bool` 开关、`number` 数字、`string` 文字、`key` 按键（捕获后保存为 Unity 的 KeyCode 名称）、`other`（嵌套 JSON，按原文写回）
- `comment` 是模组自带的说明，会跟随界面语言。**没有默认值字段**
- 配置文件位置：`mods\<模组名>\config.json`，重启游戏后生效

**游戏变速是加载器自带的功能，不是一个模组。** 它存在加载器配置里：
- `speedhackBaseSpeed`：1.0～100，1.0 表示正常速度，不支持减速
- `speedControlEnabled`：游戏内热键。Delete 在 1.0x 和上一次的倍率之间切换，Alt+= / Alt+- 调倍率

⚠ **实测（2026-11-03）**：Delete / Alt+= / Alt+- 这几个热键是**「变速」模组（SpeedHackMod）提供的**，不归加载器管。
- 关掉这个模组后热键就失效了，但加载器照样会按 `speedhackBaseSpeed` 加速。
- 所以当启动倍速大于 1 时，关掉模组会让游戏**一直卡在加速状态，切不回 1.0x**。
- 停用模组的实现方式：在 `mods/<id>/<id>.json` 里写入 `"enabled": false`，DLL 文件不动。
- 原程序在这种状态下，模组页会黑屏（原因还没查到）。

其他实测：删除**当前正在用的卡牌方案**后，会切回 `__game_default__`（游戏默认）。

⚠ **卸载 vs 停用**（2026-11-03 核对 1.3.2 `mods.js`；原型里写的"模组文件保留"是错的）：
- `modUninstall {force}`：删除加载器和**整个 `AstralParty_ModLoader` 目录，包括模组、配置、日志**，无法撤销。`force` 只用于删除不属于本工具的 version.dll。
- `modDisableLoader`：只**备份并删除 version.dll**，模组和配置都保留；之后用 `modRestoreLoader` 恢复。
- 其他相关消息：`modDownloadUpdate {overwriteDll, allowDowngrade}`、`modInstall {overwriteDll, allowDowngrade, includeSample}`。程序内置的加载器已同步到 **v3.1.3**（`Resources/ModLoader/loader-version.json`），比游戏里的 v3.1.1 新，重新安装内置版本不会降级。以后用 `tools/prepare-embedded.ps1` 同步时，如果游戏里的版本比内置的新，重新安装才会降级（`allowDowngrade`）。

**下载镜像（作者 v1.3.4 新增）：**
- `modCheckUpdate`、`modDownloadUpdate`、`modRestoreLoader` 可以多带 `mirrorType`、`customMirrorUrl`；不带就用设置里的值。新界面不带，统一在设置 → 网络里改。
- 设置字段：`librarySaveSettings` / `librarySettings` 的 `githubMirrorType`（`direct` / `gh-proxy` / `ghfast` / `custom`）、`customGitHubMirrorUrl`。**默认是 `gh-proxy`**。
- 发布包的 SHA256 清单就在下载的 zip 里，走镜像时防不住镜像改包。
- 从 v1.3.4 起 `librarySaveSettings` 缺字段时保留原值（以前会当成默认值）。

**软件自动更新（作者 v1.3.3 新增，修改版已关）：** 消息 `getAppUpdateState`、`checkAppUpdate`、`startAppUpdateDownload`、`cancelAppUpdateDownload`、`applyAppUpdate`，推送 `appUpdateState`。修改版在 `CheckAppUpdateAsync` 开头拦住，所以永远停在 `idle`。

加载器配置（`modLoaderConfig`）里还有 `enabled`、`consoleEnabled`、`debugShell`、`steamBypassEnabled`，以及若干引导和超时设置。

## 卡牌皮肤

**发出：** `skinsGetProfiles`、`skinsGetCards {name}`、`skinsSetActive {name}`、`skinsDuplicate`、`skinsUpdateMeta`、`skinsDelete {name}`、`skinsExportZip {name}`、`skinsImportZip`、`skinsImportLegacyZip`、`skinsDownloadDefault`、`skinsRestoreDefault`、`skinsOpenFolder {name?}`、`skinsPickAndReplaceCard {skinName, fileName}`、`skinsRevertCard`、`skinsPickCardAnimation`、`skinsRemoveCardAnimation`、`skinsCropSave`、`skinsAnimationCropSave`

**收到 `skinsProfiles`：** `{ profiles[], activeSkin }`
- 每个方案：`name`, `displayName`, `description`, `author`, `cardCount`, `lastModified`
- 两个特殊方案：`__game_default__`（游戏默认，不用外部图片）和 `default`。这两个都**不能删除、不能编辑信息**
- 只有 `default` 能做这两件事：「从最新 Release 下载默认包」（`skinsDownloadDefault`，覆盖同名图片，不会切换当前方案）和「恢复内置默认包」（`skinsRestoreDefault`，覆盖同名图片，并移除动态覆盖）
- ⚠ **没有「新建空白方案」**，新方案只能通过复制（`skinsDuplicate`）、导入 ZIP、导入旧式包得到
- 方案本身没有封面图字段

**收到 `skinsCards`：** `{ skinName, cards[] }`，每张卡：`cardId`, `cardName`, `category`, `fileName`, `assetKey`, `previewUrl`, `fileSizeBytes`, `isCustomized`, `isAnimated`, `canRestore`, `isSfw`
- `category` 有五类：手牌卡 / 命运卡 / 事件卡 / 地图事件 / 异画道具

### 两种导入的区别（实测，2026-11-04）

| 消息 | 适用的包 | 实际行为 |
|---|---|---|
| `skinsImportZip` | 包里直接是 PNG（`UT_HandCard_10001.png` 这类） | **只解压，不检查内容**。方案名取自 ZIP 文件名或顶层目录名 |
| `skinsImportLegacyZip` | 包里是 Unity `.bundle`（通常是给 RML 用的） | 把贴图转成 PNG，新建目录 `legacy-cards-<随机串>`，原文件留在 `source/`；不会切换当前方案；后台队列执行 |

- ⚠ **用错入口不报错**：旧式包走 `skinsImportZip` 也会提示导入成功，但方案是 0 张卡面。`skinsCards` 仍返回全部卡牌，没有自定义图片的卡回退到默认图，`isCustomized` 为 false，所以预览看起来全是官方图。设成当前方案后，游戏里也不会有变化。
- 判断方法：方案显示 0 张卡面，目录里有 `.bundle` 而没有 PNG。
- 旧式转换**只处理文件名以 `.bundle` 结尾的文件**，别的文件只复制到 `source/`。实测有的包带 `<哈希>/<哈希>/__data`（文件头是 `UnityFS`），它不会被转换，可能少一张图，内容未确认。
- 旧式转换很严格：bundle 里有非 Texture2D 资源，或贴图名不是支持的卡牌名，就拒绝整个包。
- ZIP 里套 ZIP 的发布包（外层放工具和说明，里层才是 bundle）要先解压，再导入里层的 ZIP；直接导入外层会报「ZIP 中没有 Unity .bundle 卡牌资源」（代码如此，未实际点过）。

## 角色皮肤

**发出：** `characterSkinsGet`、`characterSkinsInstall`、`characterSchemesSave`、`characterSchemesImport`、`characterSchemesExport`、`characterSchemesOpen`、`characterSchemesImportPackage`、`characterSkinsDelete`、`characterCropSave` / `characterCropCancel`

**收到 `characterSkins`：**

| 字段 | 含义 |
|---|---|
| `installed`, `updateRequired`, `installedVersion`, `bundledVersion` | 角色皮肤**模组本身**的安装状态。没装的话，方案在游戏里不生效 |
| `runtimeStatus {state, error}` | 上次进游戏时方案有没有应用成功 |
| `activeSchemeId` | ⚠ **同一时间只有一个方案处于启用状态** |
| `schemeProfiles[]` | `{ id, active, error, scheme: { name, author, description, rules[] } }` |
| `rules[]` | `{ id, heroId, officialSourceSkinItemId, customPackageId, targetSkinItemId }`，每条对应一个人物 |
| `heroes[]` | `{ id, name }` |
| `targets[]` | `{ heroId, itemId, name }`（官方皮肤名称） |
| `profiles[]` | 自定义人物包 `{ id, manifest: { name, … } }` |

每条规则的来源有三种：**官方皮肤**、**自定义皮肤**、**自定义加官方基础**。替换范围要么是"这个人物的全部原皮肤"，要么"只替换某一款皮肤"（`targetSkinItemId`）。
- 校验 1：至少要选一个官方皮肤（`officialSourceSkinItemId > 0`），或一个皮肤包
- 校验 2：同一个人物的同一款原皮肤（`heroId` 加 `targetSkinItemId`）只能有一条规则

### 人物皮肤包编辑器

**发出**（都带 `id` 指明是哪个皮肤包）：`characterSkinsCreate`、`characterSkinsSave {manifest}`、`characterSkinsImage {slot}`、`characterSkinsFrames`、`characterSkinsFrame`、`characterSkinsClearAction`、`characterSkinsExport`、`characterSkinsOpen`、`characterSkinsDelete`、`characterSkinsImport` / `characterSkinsImportLegacy`、`characterCropSave` / `characterCropCancel`

皮肤包的 `manifest` 里有：`name`, `heroId`, `author`, `skinItemId`，以及下面四块内容：

| 字段 | 内容 |
|---|---|
| `images {slot: 路径}` | 图片位置来自宿主的 `imageSlots`：完整立绘、角色头像、HUD 角色图、准备界面、战斗半身图 1/2、缩略图、窄幅图、地图像素头像、地块标志，以及对应的 SFW 版。另外还可能有 `asset:` 开头的账号背景等图片 |
| `texts {slot: 文字}` | 文案位置来自宿主的 `textSlots`：Name、Nick、Biography、Lines、SkinLong、SkinShort。留空表示使用原版。Name 和 Biography 是人物共用的，可能影响这个人物的其他皮肤 |
| `animations {动作: {fps, loop, frames[], durationsMs[]}}` | 动作名：Idle、Walk、Walk-back、Show、Talent、Hit、Hit-01、Hit-02、Cheer、Cry、Die、Eat、Hospitalized、Vomit、Lose、Electricshock |
| `layout {pivotX, pivotY, pixelsPerUnit, scale}` | 锚点 0～1，PPU 1～10000，缩放 0.01～20 |

恢复图片、改文案、改布局、改 FPS 和循环，都是改完 `manifest` 后整份用 `characterSkinsSave` 存回去。

**⚠ 从方案新建皮肤包（`CharacterSchemesModule.createPackageFromBinding`）的两个坑（2026-11-04）：**
- 它从 `characterBindingHero` 读人物，这个下拉框的选项只有原版 `openBinding` 才会填。不走 `openBinding` 就要先自己填选项，否则赋值无效、人物变成 0，创建表单的人物和皮肤都是空的，无法提交。
- 它里面的 `form.reset()` 会清空 `characterTemplateCache`。留空不报错，但导出时只搜游戏安装目录（`CharacterBundleCatalog` 会跳过不存在的路径），找不到游戏后来下载的皮肤资源。调用后要用 `data.templateCache` 填回去。

## 音效方案（1.3.2 新增，`audio-skins.js`）

**发出：**
- 方案管理：`audioSkinsGetProfiles`、`audioSkinsSetActive {id}`、`audioSkinsCreate {id, name, author, description}`、`audioSkinsDuplicate`、`audioSkinsUpdateMeta`、`audioSkinsDelete {id}`、`audioSkinsExportZip {id}`、`audioSkinsImportZip`、`audioSkinsOpenFolder`
- 条目操作（都带 `schemeId, configId, eventName`）：`audioSkinsGetItems {schemeId}`、`audioSkinsPickAndReplace {volume}`、`audioSkinsSetMute {mute}`、`audioSkinsSetVolume {volume}`、`audioSkinsRevertAudio`
- 原版音频：`audioSkinsExtractGameAudio`、`audioSkinsImportOriginalZip`、`audioSkinsExportOriginalZip`、`audioSkinsExportSingleOriginal {id, name}`

**收到：**
- `audioSkinProfiles`：`{ profiles[{ id, name, description, author, ruleCount, lastModified, isActive }], activeScheme }`
- `audioSkinItems`：`{ items[] }`，每条 `{ id, name, label, category, characterName, skinName, slotName, characterId, hasOriginal, originalPreviewUrl, previewUrl, action, customFile, volume, redirectId }`
  - `category` 有 7 类：UI 界面交互、Dice 掷骰与地图、Combat 战斗对拍、Card 卡牌与技能、Voice 角色语音、BGM 背景音乐、Misc 其它特效，共 1,322 条
  - `action` 有四种取值：`replace`（替换）、`mute`（静音）、`redirect`（重定向，界面上只显示、不能设置）、空（原版）
  - `volume` 是单条音量倍率，范围 0～2，只有替换过的条目才有
- `audioSkinExtractProgress { message, progress 0~1 }`、`audioSkinExtractDone`

**⚠ 为什么"不能播放"（2026-11-03 查明）：** 要先「提取原版音频」，把 1,322 个音频整理进游戏目录的 `audio-cache\`，或者导入离线音频包 ZIP。在这之前每条的 `hasOriginal = false`，原版界面上根本不出现「试听原版」按钮，而且没有任何地方说明原因。新界面在列表上方直接说明，并给出「准备原版音频…」按钮。

**⚠ 更正（2026-11-03 读 1.3.2 源码 + 实测）：「从游戏提取」并不解包游戏。** `AudioSkinSchemeManager.ExtractGameAudio` 只是从事先导出好的 `audio-export` 文件夹复制 `.ogg`，依次找：源码旁 `audio-export`、写死的 `C:\src\Study\astralparty\audio-export`（作者本机）、`游戏目录\audio-export`、`游戏目录\AstralParty_ModLoader\audio-export`。都没有就复制 0 个，宿主仍提示"已同步并就绪 0 个原版音频！"。作者也没公开原版音频包（CesiumLoader Release 里没有）。游戏音频是 Wwise（`wwiseId`，安装目录 `StreamingAssets\Audio` 基本是空的），真要提取得拆 Unity 资源包 → 取 .wem → ww2ogg/revorb 转 .ogg。新界面已改成照实说明，并把那句"就绪 0 个"换成实话。

- 设计决定：宿主允许修改 `default`（默认官方原版）方案，但新界面把它设成**只能试听**，要改先「复制为新方案」，保证原版始终能拿来对比。

## 市场装的模组在模组页怎么显示（实测）

市场上的名字和模组 `mod.json` 里的名字可能不一样（例如市场叫「保持神秘」，模组页显示「手牌查看」），`modStatus` 里只有后者。所以模组页把非内置模组排在前面并标「第三方」；`workshopResult.name` 和市场标题不同时，安装提示会把两个名字都写上。

## 自定义背景（修改版新增，`v2-background.js`、`HybridWindow.Background.cs`）

**发出：** `backgroundList`、`backgroundImport`（打开文件框，可多选）、`backgroundSaveFrame {file, dataUrl}`、`backgroundFrameFailed {file}`、`backgroundDelete {file}`

**收到：** `backgroundList { items[{ file, name, bytes }] }`、`backgroundFrameNeeded { file, name }`、`backgroundFrameSaved { file }`

## 深浅色模式（修改版新增）

只在页面里，不走宿主。左下角按钮切换，选择存在 localStorage 的 `v2Theme`；`index.html` 开头的小脚本在加载样式前设置 `html[data-theme="light"]`，避免先闪深色。浅色值都在 `v2.css` 末尾。

- **原版页面的浅色**：`css/v2-light.css` 由 `tools/gen-light-css.js` 从原版样式生成，不要手改。**合并作者新版后要重新运行一次** `node tools/gen-light-css.js`，作者新页面的颜色才会跟上。规则用 `:where()` 加主题条件，不增加优先级；加载顺序必须是原版样式 → `v2-light.css` → `v2.css`。新增的原版样式文件要加进脚本的 `SOURCES`。`character-skins.css` 比 `v2.css` 还晚加载，所以没有放进去。
- **切换动画**：`document.startViewTransition` 整页淡入淡出 0.5 秒，放完再冷却 0.5 秒。它的回调是**异步**的，要在回调里（`applyTheme`）才读得到新主题。关了「界面动画」就直接切，冷却还在。
- **启动画面**：页面发 `uiThemeChanged {light}`，宿主写或删设置文件夹的 `ui-theme.txt`（`HybridWindow.UiTheme.cs`），下次启动在网页加载前读取。

验证办法：在页面里遍历文字节点，算文字色和最近不透明底色的对比度，小于 3.5 的列出来。注意切换瞬间有颜色过渡，要等一下再量；列表为空的页面量不到内容。
