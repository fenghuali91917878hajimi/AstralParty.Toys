# 回放库接口（原型只用这里列出的字段）

来源：最初根据本机 1.2.12 拆出的 `WebUI/js/replay.js`、`core.js` 和上游 `HybridWindow.Replays.cs`、`Models.cs` 整理（2026-11-03）；现在基线是 1.3.2，已对照仓库源码核对。
以前标「[上游]」的 `modifiedText`、`mapId`、`winnerText` 三个字段，已确认 1.3.2 宿主会发（`HybridWindow.Replays.cs` 第 73～88 行），标记已去掉。

## 回放库是怎么做的

- 游戏自己有一个回放目录，最多存 `capacity` 局（一般是 10），这些就是「游戏内」回放。
- 工具另外建了一个「回放库」文件夹，路径在设置里改。**归档**就是把回放从游戏目录挪进库里，用来腾出游戏内的席位；**放回游戏**则反过来。
- 同一局可以两边都有，所以 `inGame` 和 `inLibrary` 可能同时为 true。
- 开启「自动托管」（`autoMaintain`）后，每次刷新列表时，宿主会把超出 `keepInGame` 的旧回放自动归档进库。
- 列表上只有从文件头读出来的简要信息（`meta`）。**点开一局才会完整解析**：宿主先发 `loading`，再发 `report`。

| 消息 | 参数 | 作用 |

## 宿主 → 前端：`replayLibrary`（列表）

整体状态：

| 字段 | 含义 |
|---|---|
| `directory`, `available` | 游戏回放目录、是否找得到 |
| `libraryRoot`, `libraryAvailable` | 回放库目录、是否可用 |
| `gameCount` / `capacity` | 游戏内席位，例如 8 / 10 |
| `libraryCount`, `librarySizeText` | 库里有几局、总共多大 |
| `keepInGame`, `autoMaintain` | 游戏内保留最近几局（1～`capacity`，设置页会把输入限制在这个范围）、是否开启自动托管 |
| `gameFull`, `gameOverKeep` | 席位满了 / 超过保留数 |
| `gameRunning` | 游戏是否在运行 |
| `sameFolder` | 库目录和游戏目录是同一个（这时不能归档） |
| `upgradeTargetVersion` | 工具支持的游戏版本 |
| `warnings[]` | 文字警告 |
| `entries[]` | 每一局，见下表 |

每一局（`entries[]`）：

| 字段 | 含义 | 没有数据时 |
|---|---|---|
| `token` | 打开这一局时要用的令牌（`replay-0` 这种），每次刷新都会变 | — |
| `replayId` | 回放 ID | — |
| `inGame`, `inLibrary` | 在哪一边，可能两边都在 | — |
| `healthy`, `error` | 能不能解析、失败原因 | `false` / `""` |
| `finishText` | 对局结束时间 `yyyy-MM-dd HH:mm` | `—` |
| `modifiedText` | 文件修改时间 | `—` |
| `sortTime` | 排序用的时间戳 | — |
| `durationText` | 时长 `hh:mm:ss` | `—` |
| `mapName`, `mapId` | 地图 | `未知地图` |
| `roundCount`, `frameCount` | 回合数、帧数 | `0` |
| `gameVersion` | 游戏版本 | `—` |
| `canUpgrade`, `isCurrentVersion`, `isNewerVersion` | 版本比较结果 | — |
| `playersText` | 玩家昵称，用 ` · ` 连成一串 | `—` |
| `heroesText` | 角色名，顺序和玩家一一对应 | `—` |
| `winnerText` | 决胜者 | `—` |
| `sizeText`, `sizeBytes` | 文件大小 | — |

**列表里没有的东西：** 名次、"哪个玩家是我"、难度、模式、头像。难度要点开一局（拿到 `report`）才有。

**获胜方是怎么来的**（2026-11-03 核对上游 `ReplayLibraryService.cs` / `ReplayAnalyzer.cs`）：
- 回放结算帧里有一个 `Winer` 字段（原文就是这么拼的），存的是**玩家 ID**，所以一局里有一个获胜玩家，但**没有完整排名**。
- 列表的 `winnerText`：先用 ID 去找对应的昵称，找不到就显示 `玩家 <ID>`，没有记录时是 `—`。
- `report.match.winnerText`：只会是 `获胜方 <ID>` 或 `未记录获胜方`，**不带昵称**。所以详情页想显示名字，得用列表里的 `winnerText`。
- `report.match.resultText`：只有两种值，`胜利`（有获胜方时）和 `已结束`。**没有"失败"**。
- `report.match.awardsText`：形如 `道具名 ×数量`，多个用 ` · ` 连接；没有时是 `未记录奖励`。
- 玩家的 `finalBossKill`（原版界面显示成"决胜"）表示击杀了最终首领，和"获胜方"不是一回事。

## 宿主 → 前端：`report`（打开一局之后）

- `report.file`：`fileName`, `fileSizeText`
- `report.match`：`mapName`, `mapImage`, `difficulty`, `bossName`, `resultText`, `winnerText`, `awardsText`, `durationText`, `roundCount`, `progressText`, `playerDeaths`, `frameCount`
- `report.players[]`：`id`, `nickname`, `heroName`, `avatar`, `accountLevel`, `finalStatus`, `finalBossKill`, `hpText`, `gold`, `transferGold`, `attack`, `defense`, `damage`, `injured`, `kills`, `movePoints`, `usedCards`, `usedSkills`, `selectedRelicCount`, `selectedRelics[]`
- `report.performance[]`：`playerId`, `points[]`（逐回合：`round`，`damage` / `transfer` / `cards` / `earnedGold` / `currentGold` / `deaths` / `kills`，以及各自的 `…Delta`）, `dice[]`
- `report.events[]`：`frameIndex`, `round`, `roundText`, `playerName`, `type`, `title`, `description`
- `report.relics[]`：`round`, `playerName`, `heroName`, `source`, `kind`, `relicId`, `relicName`, `quality`, `refreshText`, `options[]`, `optionsText`, `frameIndex`
- `report.shops[]`：`round`, `playerId`, `playerName`, `heroName`, `shopType`, `optionsText`, `priceText`, `hasPurchase`, `purchaseText`, `boughtText`, `soldOutText`
- `report.monsters[]`, `report.monsterTileSteps[]`, `report.monsterSummary`：怪物统计
- `report.frames[]`, `report.statistics`：专业信息（协议帧、命令统计）
